# Contributing and getting support

This repository hosts the DevPulse product website and public support tracker. The application for macOS, iOS and iPadOS source is maintained separately. Public contributions are accepted as **issues**, not pull requests.

## Before opening an issue

- Read the [support guide](https://chrominskyy.github.io/devpulse-site/support.html) and search existing issues.
- Choose the bug report, feature request, or support question template.
- Write in English or Polish. Use one issue per problem or request.
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md).

## Bug reports

Identify whether the problem concerns the macOS/iOS/iPadOS app or the website. Include the app version, platform and operating-system version for app problems, or browser and operating system for website problems. Describe reproduction steps, the expected result, and the actual result. Use a minimal synthetic example when needed. Never include your organization’s pipeline definitions, logs or work items.

## Feature requests and questions

Describe the task you are trying to complete, what is missing, and any workaround. A request does not guarantee implementation or a release date. For questions, include what you have already tried.

## Keep reports safe

Issues and attachments are public. Do not upload private documents, personal details, passwords, PATs, access tokens, authorization headers, or unredacted pipeline logs. Remove private paths and account details from screenshots. Report security vulnerabilities privately using [the security policy](SECURITY.md).

## Maintainer workflow

Pull requests, Discussions, Wiki, Projects and commit comments are disabled. Maintainers review issues and may request more information, link duplicates, or close reports outside this repository's scope. No response-time guarantee is provided.

The pull request template is retained for maintainer use if pull requests are enabled in the future; it does not change the current contribution policy.

## Rights

Public visibility does not make the app, website, artwork, or documentation open source. See [LICENSE](LICENSE). Sharing a report does not transfer ownership of your documents or attachments.
